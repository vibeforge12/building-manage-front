## 1. 개요

프론트엔드 앱 배포는 **Fastlane**으로 수행한다. iOS/Android 모두 지원하며, 로컬 Mac에서 수동 실행한다. 장기적으로 GitHub Actions 등 CI로 이식 가능하도록 설계되어 있다.

### 1.1 지원되는 배포 시나리오

| 대상 | 레인 | 트랙/대상 |
|------|------|----------|
| iOS TestFlight | `fastlane ios beta` | TestFlight |
| iOS 프로덕션 | `fastlane ios production` | TestFlight + **App Store 심사 자동 제출** |
| Android 내부 테스트 | `fastlane android internal` | Play Internal Testing |
| Android 프로덕션 | `fastlane android production` | Play Production (심사 자동 제출) |
| 양쪽 플랫폼 동시 (내부 테스트) | `fastlane release_internal` | iOS TestFlight + Android Internal |
| 양쪽 플랫폼 동시 (프로덕션) | `fastlane release_production` | iOS App Store 심사 + Android Production 심사 |

**4가지 선택 패턴**:
1. 양쪽 프로덕션 → `release_production`
2. 양쪽 내부 테스트 → `release_internal`
3. 단일 플랫폼 프로덕션 → `ios production` / `android production`
4. 단일 플랫폼 내부 테스트 → `ios beta` / `android internal`

### 1.2 아키텍처

3-tier Fastlane 구조:

- **루트 `fastlane/Fastfile`** — 크로스플랫폼 공통 레인 (버전 관리, 동시 배포)
- **`ios/fastlane/Fastfile`** — iOS 전용 레인
- **`android/fastlane/Fastfile`** — Android 전용 레인

`pubspec.yaml`의 `version: X.Y.Z+B`가 iOS `CFBundleVersion`과 Android `versionCode` 양쪽의 **단일 소스**. 플랫폼 간 버전 드리프트가 구조적으로 불가능.

## 2. 사전 요구사항

### 2.1 환경

- macOS
- Homebrew Ruby 4.x (시스템 Ruby 2.6은 호환 불가)
- CocoaPods 1.16+ (iOS 빌드용)
- Flutter 3.32.1 (`.fvm/fvm_config.json`에 핀됨)
- Xcode 16+ (iOS 빌드용)
- Android Studio 또는 JDK 11+ (Android 빌드용)

### 2.2 설치 (최초 1회)

```bash
# Homebrew Ruby 설치
brew install ruby

# PATH 추가 (~/.zshrc에 영구 저장 권장)
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"

# CocoaPods 설치 (iOS 배포 시)
brew install cocoapods

# fvm 설치 (Flutter 버전 관리)
brew tap leoafarias/fvm
brew install fvm

# 프로젝트로 이동
cd "/path/to/building-manage-front"

# 프로젝트 pin된 Flutter 버전 설치
fvm install 3.32.1
fvm use 3.32.1

# Ruby gems 설치
bundle install
```

## 3. 인증 파일 배치

모든 민감한 자격증명은 **repo 외부** `../private_keys/` 디렉토리에 둔다. repo에는 절대 커밋하지 않는다.

```
Building Manager/                    ← repo의 부모 디렉토리
├── building-manage-front/           ← repo (git 관리 대상)
└── private_keys/                    ← git에 없음
    ├── AuthKey_{KEY_ID}.p8          # iOS App Store Connect API Key
    ├── building_manage.jks          # Android 서명용 keystore
    └── play-service-account.json    # Google Play API Service Account
```

### 3.1 iOS — App Store Connect API Key (.p8)

1. App Store Connect → 사용자 및 액세스 → API 키 생성 (관리자 권한 필요)
2. Key ID, Issuer ID, Team ID 기록
3. `.p8` 파일을 `../private_keys/AuthKey_{KEY_ID}.p8`에 배치
4. `ios/fastlane/Appfile`, `ios/fastlane/Fastfile`에 팀/키 정보 설정 (각 `.example` 파일 참조)

### 3.2 Android — Keystore + Service Account

**Keystore (서명용)**:
1. `building_manage.jks`를 `../private_keys/`에 배치
2. `android/key.properties` 생성 ([`android/key.properties.example`](../android/key.properties.example) 참조):
   ```properties
   storeFile=/absolute/path/to/private_keys/building_manage.jks
   storePassword=...
   keyAlias=building_manage_key
   keyPassword=...
   ```
3. `android/app/build.gradle.kts`가 이 파일을 자동으로 읽어 서명 설정에 주입

**Google Play Service Account (업로드용)**:
1. Google Cloud Console → **Play Console과 연결된 GCP 프로젝트** 선택
2. API 라이브러리에서 **"Google Play Android Developer API"** 사용 설정
3. IAM → 서비스 계정 생성 (예: `fastlane-publisher`)
4. JSON 키 다운로드 → `../private_keys/play-service-account.json`로 배치
5. Play Console → **사용자 및 권한** → 서비스 계정 이메일 주소로 초대, 최소 권한:
   - ✅ 릴리스 생성 및 수정
   - ✅ 테스트 출시
   - ✅ 프로덕션 출시
   - ✅ 앱 정보 및 기본 스토어 등록정보 보기
6. 권한 전파에 최대 24시간이 걸릴 수 있음 (보통 수 분)

## 4. 일상적인 배포 명령어

모든 명령은 **프로젝트 루트에서** 실행. 개별 플랫폼 명령만 해당 디렉토리 이동.

```bash
cd "/path/to/building-manage-front"
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
```

### 4.1 버전 관리 (루트 레벨)

```bash
bundle exec fastlane show_version                    # 현재 버전 확인
bundle exec fastlane bump_build                      # 빌드번호 +1 (iOS/Android 공통)
bundle exec fastlane bump_version version:1.1.0      # 마케팅 버전 변경
```

### 4.2 양쪽 플랫폼 동시 배포 (권장)

```bash
# 내부 테스트: bump + iOS TestFlight + Android Internal
bundle exec fastlane release_internal

# 프로덕션 심사: bump + iOS App Store 심사 + Android Production 심사
bundle exec fastlane release_production
```

`release_production` 동작: iOS 는 `ios production` 호출(TestFlight 업로드 + App Store 심사 제출), Android 는 `android production` 호출(Play Production 업로드 + 심사 자동 제출). 두 스토어 모두 **승인 후 수동 출시** 가 기본값.

### 4.3 개별 플랫폼 배포

**iOS:**
```bash
cd ios
bundle exec fastlane ios beta              # 빌드 + TestFlight 업로드
bundle exec fastlane ios production        # 빌드 + TestFlight + App Store 심사 제출
bundle exec fastlane ios submit_review     # TestFlight 최신 빌드를 App Store 심사 제출 (빌드 안 함)
bundle exec fastlane ios build             # IPA 빌드만
bundle exec fastlane ios upload            # 기존 IPA만 TestFlight 업로드
```

`submit_review`는 이미 TestFlight 에 있는 빌드를 별도 재빌드 없이 심사에만 넘기고 싶을 때 사용.

**Android:**
```bash
cd android
bundle exec fastlane android internal             # 빌드 + Internal 업로드
bundle exec fastlane android production           # 빌드 + Production 업로드 (심사 자동 제출)
bundle exec fastlane android build                # AAB 빌드만
bundle exec fastlane android upload_internal      # 기존 AAB → Internal
bundle exec fastlane android upload_production    # 기존 AAB → Production
```

## 5. 프로덕션 배포 시 주의사항

### 5.1 Managed Publishing (Android, 필수)

Play Console → 해당 앱 → **게시 개요(Publishing overview)** → **"관리되는 게시" 토글 ON**

- **ON**: 심사 통과 후 "게시 대기" 상태로 정지 → Play Console에서 사용자가 수동으로 "게시" 클릭 시 실제 공개 ✅ (권장)
- **OFF**: 심사 통과 즉시 100% 전체 공개 ⚠️

이 토글은 **앱 전역 설정**이며 한 번 켜면 모든 후속 프로덕션 릴리스에 적용된다.

### 5.1-2 iOS App Store 수동 출시 (기본값)

`fastlane ios production` 은 `automatic_release: false` 로 심사 제출하므로, 심사 통과 후 **App Store Connect → "이 버전 출시" 버튼 수동 클릭** 이 필요. Android 의 "관리되는 게시" 와 동일 패턴.

자동 공개를 원하면 `ios/fastlane/Fastfile` 의 `submit_review` 레인에서 `automatic_release: true` 로 변경.

### 5.2 versionCode 관리

`pubspec.yaml`의 `+buildNumber`가 자동으로 iOS `CFBundleVersion` + Android `versionCode`로 변환된다.

- **Play Store**: versionCode 재사용 **절대 불가** (전체 앱 history에서 unique)
- **TestFlight**: 같은 marketing version 내에서 CFBundleVersion unique
- Internal 트랙과 Production 트랙은 **서로 다른 versionCode** 필요 (한 binary를 두 트랙에 못 쓰거나, 승격[promote]은 별도 API)

실용 규칙: `bump_build`를 릴리스 **사이클당 1회**만 실행하고, 실패 후 재시도 시에도 같은 pubspec 상태로 재시도한다. Internal + Production 동시 배포 시엔 자동으로 2회 bump됨.

### 5.3 프로덕션 심사 소요 시간

Google Play 심사: 보통 **1-3일**. 이메일로 결과 통지.

## 6. CI/CD 환경에서 실행

Fastlane 커스텀 레인의 `UI.confirm` safety prompt는 **대화형 TTY**가 필요하다. CI 서버(비대화형)에서는 prompt 우회 필요.

### 6.1 액션 직접 호출 (prompt 우회)

```bash
bundle exec fastlane run upload_to_play_store \
  json_key:"../private_keys/play-service-account.json" \
  package_name:"com.j2partners.buildingManageFront" \
  aab:"build/app/outputs/bundle/release/app-release.aab" \
  track:"production" \
  release_status:"completed" \
  skip_upload_apk:"true" \
  skip_upload_metadata:"true" \
  skip_upload_changelogs:"true" \
  skip_upload_images:"true" \
  skip_upload_screenshots:"true"
```

이 패턴은 Fastfile의 래퍼 레인을 거치지 않고 Fastlane `supply` 액션을 직접 호출하므로 `UI.confirm`에 걸리지 않는다.

### 6.2 GitHub Actions 예시 (미래 확장용)

```yaml
- name: Deploy to Play Internal
  env:
    PLAY_KEY_JSON: ${{ secrets.PLAY_SERVICE_ACCOUNT_JSON }}
  run: |
    echo "$PLAY_KEY_JSON" > /tmp/play-key.json
    cd android
    bundle exec fastlane run upload_to_play_store \
      json_key:/tmp/play-key.json \
      package_name:com.j2partners.buildingManageFront \
      aab:../build/app/outputs/bundle/release/app-release.aab \
      track:internal \
      release_status:draft \
      skip_upload_apk:true \
      skip_upload_metadata:true \
      skip_upload_changelogs:true \
      skip_upload_images:true \
      skip_upload_screenshots:true
```

## 8. 트러블슈팅

### 8.1 "Could not find 'bundler' (X.X.X) required by your Gemfile.lock"
- **원인**: 시스템 Ruby(2.6)가 너무 낮음
- **해결**: Homebrew Ruby 4.x 사용
  ```bash
  export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
  ```
  이 줄을 `~/.zshrc`에 영구 저장 권장

### 8.2 "The current Dart SDK version is X.X, Because building_manage_front requires ^3.8.1"
- **원인**: FVM이 낡은 Flutter 버전을 가리킴
- **해결**: 프로젝트 루트에서
  ```bash
  fvm use 3.32.1
  ```

### 8.3 "Google Api Error: Invalid request - The caller does not have permission"
- **원인**: Play Console에서 서비스 계정에 앱 권한 미부여
- **해결**: Play Console → 사용자 및 권한 → 서비스 계정 이메일(`*.iam.gserviceaccount.com`)로 초대하여 "릴리스 생성 및 수정" + "테스트 출시" + "프로덕션 출시" 권한 부여. 권한 전파에 최대 24시간 가능 (보통 수 분)

### 8.4 "Google Api Error: Invalid request - Version code X has already been used"
- **원인**: Play Store에 이미 사용된 versionCode로 업로드 시도
- **해결**: `bundle exec fastlane bump_build` 후 재실행. versionCode는 **영구 유일**이라 재사용 불가. 과거에 수동 업로드 이력이 있다면 Play Console의 현재 최고 번호보다 큰 값으로 점프 필요

### 8.5 "Could not retrieve response as fastlane runs in non-interactive mode"
- **원인**: `UI.confirm` 프롬프트가 있는 레인을 비대화형 shell(pipe, subprocess)에서 실행
- **해결**: 실제 터미널에서 직접 실행하거나, 6.1의 `fastlane run <action>` 직접 호출 패턴 사용

### 8.6 "CocoaPods is installed but broken"
- **원인**: CocoaPods가 시스템 Ruby로 설치되어 Homebrew Ruby와 충돌
- **해결**: `brew install cocoapods`로 재설치

### 8.7 "Unable to flip between RX and RW memory protection" (iOS 18.4+)
- **원인**: iOS 18.4+ debug 모드 JIT 제한
- **해결**: Release 모드 사용 (`flutter run --release`), 또는 기기에서 개발자 모드 활성화

## 9. 보안

**절대 git에 올리지 말 것** (모두 `.gitignore`에 등록됨):

| 파일 | 이유 |
|------|------|
| `../private_keys/*.p8` | iOS App Store Connect API 개인키 |
| `../private_keys/*.jks` | Android keystore (앱 서명의 뿌리) |
| `../private_keys/*.json` | Google Play Service Account (JWT 서명용 RSA 개인키 포함) |
| `android/key.properties` | keystore 비밀번호 |
| `ios/fastlane/Fastfile`, `Appfile` | Key ID, Issuer ID, 팀 ID |
| `android/fastlane/Fastfile`, `Appfile` | 패키지명, JSON 경로 |

### 9.1 유출 시 대응

| 자격증명 | 대응 |
|---------|------|
| iOS API Key (`.p8`) | App Store Connect에서 즉시 revoke, 새 키 발급 |
| Play Service Account JSON | Google Cloud Console → 해당 키 disable + 새 키 생성 + Play Console 권한 재등록 |
| Android Keystore (`.jks`) | **교체 불가** (앱 서명 연속성 때문). 유출되면 비상사태 — 앱 이관 절차 필요 |

### 9.2 정기 점검

- 매 분기: Service Account JSON 회전
- 매 6개월: API Key(.p8) 회전
- 매 릴리스: `git log -p private_keys/` 같은 민감 경로가 커밋에 섞이지 않았는지 확인
