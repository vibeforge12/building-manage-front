## 1.5 인증 흐름 — 끝까지 추적

### (1) 토큰 저장 위치

**`flutter_secure_storage`** 입니다. `SharedPreferences`가 아닙니다.

`lib/core/network/interceptors/auth_interceptor.dart:12-17`
```dart
static const FlutterSecureStorage _secureStorage = FlutterSecureStorage(
  aOptions: AndroidOptions(encryptedSharedPreferences: true, resetOnError: true),
);
```
키: `access_token`, `refresh_token` (`auth_interceptor.dart:5-6`)

`SharedPreferences`는 다른 용도로만 씁니다: 앱 버전 플래그(`main.dart:89-96`), 승인완료 화면 1회 노출 플래그(`user_login_screen.dart:79-85`, `splash_screen.dart:64-66`).

### (2) 요청에 토큰이 붙는 방법

`auth_interceptor.dart:20-46` — 매 요청마다 SecureStorage를 읽어 `Authorization: Bearer <token>` 헤더를 추가합니다. 단, 아래 공개 엔드포인트는 제외:

```
/auth/resident/register, /auth/manager/register,
/auth/resident/login, /auth/manager/login, /auth/staff/login, /auth/headquarters/login,
/auth/refresh
```

### (3) 로그인 성공 시 토큰 저장 — **경로가 두 개**

- 경로 A: `AuthInterceptor.onResponse` (`auth_interceptor.dart:49-57`) — 응답 path에 `/login`이 포함되고 200이면 자동 저장
- 경로 B: `AuthStateNotifier.loginSuccess` (`auth_state_provider.dart:46-65`) — 화면에서 명시적으로 `AuthInterceptor.saveToken()` 호출

두 경로가 동시에 동작하므로 같은 토큰을 두 번 씁니다. 기능상 문제는 없으나 책임이 중복돼 있습니다.

### (4) 401이 나면 무슨 일이 벌어지는가 — ✅ **해결됨 (2026-08-21). 초판 서술은 전면 무효**

> ~~"CLAUDE.md 가 401 자동 갱신을 단언하지만 사실이 아닙니다."~~
> → `auth_interceptor.dart` 가 **표준 refresh 큐 패턴을 전부 구현**했습니다. `CLAUDE.md` 서술이 이제 사실입니다.

현재 `AuthInterceptor.onError` (`auth_interceptor.dart:67-124`) 의 분기 순서:

| # | 조건 | 동작 | 근거 |
|---|---|---|---|
| 1 | 401 이 아님 | 그대로 통과 | `auth_interceptor.dart:70-73` |
| 2 | path 에 `/login` 또는 `/register` | **토큰 유지**, 그대로 통과 (= "로그인 실패") | `:80-85` |

**동시 401 처리 (갱신 1회 공유)** — `_refreshAccessToken()` (`auth_interceptor.dart:127-139`):
```dart
static Future<String?>? _refreshFuture;   // :14

Future<String?> _refreshAccessToken(RequestOptions options) {
  final ongoingRefresh = _refreshFuture;
  if (ongoingRefresh != null) return ongoingRefresh;   // 진행 중이면 그 Future 를 공유
  final refreshFuture = _performRefresh(options).whenComplete(() => _refreshFuture = null);
  _refreshFuture = refreshFuture;
  return refreshFuture;
}
```

**갱신·재시도 요청의 재귀 방지**: `_createPlainDio()` (`auth_interceptor.dart:188-198`) 로
인터셉터가 없는 별도 Dio 를 만들어 사용하므로 `AuthInterceptor` 를 다시 타지 않습니다.

**P0-1 (비밀번호 오타로 로그아웃) 도 함께 해소**: `/auth/resident/change-password` 나
`DELETE /users/me` 의 401 은 위 표 5번으로 들어가고, refresh 가 성공하면 토큰이 유지된 채
원 요청이 재시도되어 서버의 "비밀번호 불일치" 응답을 그대로 받습니다.

### (5) 토큰 갱신 호출처 — ✅ **해결됨 (2026-08-21). 초판 서술 무효**

> ⚠️ ~~"`AuthRemoteDataSource.refreshToken()` 의 유일한 호출자는 `checkAutoLogin()` 이며,
> 토큰 갱신은 앱 시작 시 1회만 일어난다"~~ → **무효.**

`AuthInterceptor._performRefresh()` (`auth_interceptor.dart:142-184`) 가
`POST ApiEndpoints.refreshToken` 을 **직접** 수행합니다. 따라서 앱 사용 중 access token 이 만료되면
그 시점의 401 이 자동으로 갱신을 트리거합니다.

- 응답 파싱은 `data['data']` 래핑과 평면 응답을 모두 허용 (`:162-164`)
- `accessToken` 은 필수, `refreshToken` 은 있으면 회전 저장 (`:166-177`)
- 실패 시 `null` 반환 → 호출부가 토큰 삭제 (`:180-183`)

`AuthStateNotifier.checkAutoLogin()` 경로(앱 시작 시 1회)는 **여전히 별도로 존재**하며,
`/auth/refresh` 응답에 `user` 객체가 없으면 실패 처리하는 문제(아래 (6) ★)는 **그대로입니다.**

### (6) 자동 로그인 — 언제 어디서 호출되나

**`main.dart`가 아니라 `SplashScreen`에서 호출합니다.** (`CLAUDE.md`는 `main.dart`라고 기술 — 오기)

## 4.3 혼동 위험 지점 — 반드시 인지해야 할 3가지

### ⚠️ (1) `headquarters/` 모듈의 `manager_*` 파일들은 **관리자(admin)** 화면입니다
- `headquarters/presentation/screens/manager_list_screen.dart` — 본사가 보는 **관리자 목록** (`/headquarters/managers`)
- `headquarters/presentation/screens/manager_detail_screen.dart` — **관리자 상세**
- `common/data/datasources/manager_list_remote_datasource.dart` — **관리자 목록 API**
- 라우트도 `/headquarters/manager-list`, `/headquarters/manager-detail/:managerId` (`router_notifier.dart:613, 620`)

프로젝트 규칙(`manager` = 담당자)과 정면으로 충돌합니다. "담당자 목록"으로 오해해 담당자 API(`/staffs`)를 붙이면 잘못된 데이터를 다루게 됩니다.
**권장**: `admin_list_screen` / `admin_detail_screen` / `admin_list_remote_datasource`로 리네이밍.

### ⚠️ (2) `manager/` 모듈에 관리자용 파일이 섞여 있습니다
- `manager/data/datasources/general_manager_remote_datasource.dart` — 총관리자(HEAD)가 일반관리자(GENERAL)를 추가하는 **관리자(admin) 기능**. `POST /managers/general-managers`
- `manager/presentation/screens/add_general_manager_screen.dart` — 위 화면
- 라우트 `/manager/add-general-manager` (`router_notifier.dart:507`)의 주석은 "일반관리자 추가 (총관리자 전용)"
- `User.managerType`(`domain/entities/user.dart:35`)의 `HEAD`/`GENERAL`은 **관리자 계정에만 존재**한다고 명시돼 있음

**권장**: 이 3개를 `modules/admin/`으로 이동하고 라우트를 `/admin/add-general-manager`로 변경. (라우트 변경 시 참조처 함께 수정 필요)

### ⚠️ (3) `UserType.manager.code == 'STAFF'`, `UserType.admin.code == 'MANAGER'`
- `app/app.dart:129` — `final userType = user.userType.code.toLowerCase();`
- `notification_service.dart:136-171` — `'manager'` → `/managers/push-token`(관리자), `'staff'` → `/staffs/push-token`(담당자)

현재 매핑은 **정확합니다**. 다만 `UserType.manager` → 문자열 `'staff'`라는 이중 반전이 있으므로, 이 부분을 만질 때 매핑 테이블을 반드시 함께 확인해야 합니다.
